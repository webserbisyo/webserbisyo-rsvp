# React 19 Rules - WebSerbisyo RSVP

Verified against official React 19 / 19.2 docs and releases as of 2026-04-27.

Use the installed `package.json` / `package-lock.json` as the project source of truth. Do not upgrade React blindly. Before upgrading React, React DOM, or hook lint tooling, check official React release notes and run all checks.

Current stable target: React `19.2.x`.

---

## 1. Next.js App Router Default

In this RSVP app, components under `src/app` are Server Components by default.

Rules:

- Prefer Server Components for pages, layouts, static sections, and server-side reads.
- Add `"use client"` only for interactivity, browser APIs, local state, effects, or client-only libraries.
- Push `"use client"` to leaf components, not whole pages/layouts.
- Keep business logic out of components.
- Put mutations in `src/server/actions`.
- Put workflows in `src/server/services`.
- Put reads in `src/server/queries`.

Good pattern:

```tsx
// Server Component
export default async function AdminPage() {
  const applications = await getApplications();

  return <ApplicationsTable applications={applications} />;
}
```

```tsx
"use client";

export function ApplicationsTable({ applications }: Props) {
  // sorting/filtering/dialog state only
}
```

---

## 2. When to Use Client Components

Use `"use client"` for:

- `useState`
- `useEffect`
- `useRef`
- event handlers
- browser APIs like `window`, `localStorage`, `navigator`
- React Hook Form
- shadcn interactive components when required
- client-only charts, dialogs, menus, or toasts

Do not add `"use client"` just because a component renders UI.

---

## 3. React Actions and Forms

Use React 19 form/action patterns for RSVP forms and admin mutations.

For client form state with Server Actions, use `useActionState` from `react`.

```tsx
"use client";

import { useActionState } from "react";
import { submitApplicationAction } from "@/server/actions/applications";

const initialState = {
  ok: false,
  error: null as string | null,
};

export function ApplicationForm() {
  const [state, action, isPending] = useActionState(submitApplicationAction, initialState);

  return (
    <form action={action}>
      {/* fields */}
      <button disabled={isPending}>{isPending ? "Submitting..." : "Submit application"}</button>
      {state.error ? <p>{state.error}</p> : null}
    </form>
  );
}
```

Rules:

- Use Zod in Server Actions for external input.
- Return typed action state.
- Disable submit buttons while pending.
- Do not trust client-side validation only.
- Do not use old `useFormState`.

---

## 4. useFormStatus

Use `useFormStatus` from `react-dom` for submit buttons nested inside forms.

```tsx
"use client";

import { useFormStatus } from "react-dom";

export function SubmitButton({ children }: { children: React.ReactNode }) {
  const { pending } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? "Submitting..." : children}
    </button>
  );
}
```

Rules:

- `useFormStatus` must be used inside a component rendered within a `<form>`.
- Prefer this for reusable submit buttons.
- Keep form pending UI simple for MVP.

## 5. useOptimistic

Use `useOptimistic` only when optimistic UI adds real value.

Good future RSVP uses:

- Guest RSVP status update
- Guestbook moderation toggle
- Admin application status quick update
- Dashboard response list update

Do not use it for the first version of critical admin approval/payment flows unless rollback and error states are clear.

Rule:

```txt
Optimistic UI is optional.
Correct backend truth is required.
```

## 6. useEffectEvent

Use `useEffectEvent` for event-like callbacks inside Effects that need latest props/state without reconnecting/re-subscribing.

Possible future use:

- dashboard realtime subscriptions
- notification listeners
- browser event listeners
- analytics event listeners

Rules:

- Do not use it just to silence dependency warnings.
- Do not put Effect Events in dependency arrays.
- Keep the Effect dependencies honest.
- Ensure hook lint tooling supports React 19.2 behavior.

Example:

```tsx
"use client";

import { useEffect, useEffectEvent } from "react";

export function Subscription({ clientId, theme }: Props) {
  const onMessage = useEffectEvent((message: string) => {
    showToast(message, theme);
  });

  useEffect(() => {
    const unsubscribe = subscribeToClient(clientId, onMessage);
    return unsubscribe;
  }, [clientId]);

  return null;
}
```

## 7. Activity

`<Activity />` can preserve hidden UI state while controlling visibility.

Use only when it clearly helps:

- multi-step forms where hidden step state must be preserved
- dashboard tabs with expensive content
- future RSVP editor sections

Do not use it for simple conditional rendering.

```tsx
import { Activity } from "react";

<Activity mode={activeTab === "details" ? "visible" : "hidden"}>
  <EventDetailsForm />
</Activity>;
```

Rules:

- `visible` shows children and processes updates normally.
- `hidden` hides children, unmounts effects, and defers updates.
- Avoid adding it during scaffold unless needed.

---

## 8. use()

The `use()` API can read promises or context during render.

Rules:

- In Next.js Server Components, prefer normal `async/await`.
- In Client Components, use `use()` sparingly with Suspense.
- Do not replace simple data fetching patterns with `use()` unnecessarily.
- Do not use `use()` to hide unclear data boundaries.

For this RSVP MVP, `use()` is rarely needed early.

## 9. Ref and Context Patterns

React 19 supports `ref` as a prop for function components.

For new custom components:

```tsx
type InputProps = React.ComponentProps<"input"> & {
  ref?: React.Ref<HTMLInputElement>;
};

export function TextInput({ ref, ...props }: InputProps) {
  return <input ref={ref} {...props} />;
}
```

Rules:

- Prefer ref-as-prop for new custom components when practical.
- Do not rewrite shadcn/Radix generated components just to remove `forwardRef`.
- Existing `forwardRef` code is acceptable if generated or library-driven.

React 19 also supports rendering `<Context>` directly as a provider.

For new custom context:

```tsx
<ThemeContext value={theme}>{children}</ThemeContext>
```

Rules:

- Prefer direct `<Context>` for new custom contexts.
- Do not churn existing generated/library code just to replace `<Context.Provider>`.

## 10. React Hook Form

Use React Hook Form only for real forms that need client-side field state, validation messages, or controlled UI.

Rules:

- Prefer Zod schemas shared with Server Actions.
- Use `useWatch` instead of broad `watch()` subscriptions for reactive field behavior.
- Keep form components client-side, but keep submit/business logic server-side.
- Do not place service-role or private logic in form components.

Good RSVP uses:

- `/apply` application form
- client event setup form later
- gift wallet settings later
- guestbook settings later

---

## 11. Hydration Safety

Avoid hydration mismatches.

Do not render changing values directly during SSR:

- `Date.now()`
- `Math.random()`
- browser-only locale formatting
- `window` checks that change rendered markup
- localStorage-dependent initial markup

Use Client Components/effects for browser-only values.

Bad:

```tsx
<p>{new Date().toLocaleString()}</p>
```

Better:

```tsx
"use client";

import { useEffect, useState } from "react";

export function ClientTime() {
  const [value, setValue] = useState("");

  useEffect(() => {
    setValue(new Date().toLocaleString());
  }, []);

  return <p>{value}</p>;
}
```

---

## 12. Suspense

Use Suspense intentionally.

Good uses:

- route `loading.tsx`
- server data sections with clear fallback
- future dashboard sections with independent loading

Do not wrap everything in Suspense without a reason.

Keep loading states simple for the MVP.

## 13. Imports

Preferred React 19 imports:

```tsx
import {
  Activity,
  Suspense,
  use,
  useActionState,
  useEffect,
  useEffectEvent,
  useOptimistic,
  useRef,
  useState,
  useTransition,
} from "react";

import { useFormStatus } from "react-dom";
```

Only import what is used.

Avoid:

```tsx
import { experimental_useFormState } from "react-dom";
```

---

## 14. RSVP MVP Usage Priority

Use React 19 features in this order:

```txt
1. Server Components by default
2. Leaf Client Components only when needed
3. useActionState for form Server Actions
4. useFormStatus for reusable submit buttons
5. useOptimistic only after backend truth is stable
6. useEffectEvent only for real subscriptions/listeners
7. Activity only for state-preserving tabs/steps
8. use() rarely; prefer async Server Components
```

---

## 15. Anti-Patterns

Avoid:

```txt
"use client" at page/layout level without need
business logic inside components
service-role Supabase in client components
client-only validation as the only validation
old useFormState
overusing useOptimistic for critical payment/admin workflows
using Activity for simple conditional rendering
rewriting shadcn/Radix internals just to remove forwardRef
broad React Hook Form watch() when useWatch is enough
hydration-unsafe Date.now()/Math.random() SSR output
copying POS component/state patterns into RSVP
```
